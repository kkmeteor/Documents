## 二、AI 编码工具行业速览（5 min）

| 排名 | 工具 | 公司 | 份额 | 特点 |
|-----|------|------|------|------|
| 1 | GitHub Copilot | Microsoft/GitHub | ~42% | 全球最广泛，VS Code 深度集成 |
| 2 | Trae | 字节跳动 | ~41%（国内） | AI 原生 IDE，多模态开发 |

| 8 | CodeGeeX/Fitten Code | 智谱AI/清华 | 5-7% | 完全免费，各有特色 |

### 2.2 关键趋势
- **个体渗透率已很高**（84%），但深度 Agent 化部署仅 **16%**
- **国内工具性价比优势明显**：国产月费 ¥0-200 vs 国际 $10-120
- **多模型策略成为标配**：DeepSeek（Token 消耗第一）、Claude（企业 API 支出 40%）、GPT 多强并存
- **AI 原生 IDE 冲击传统 IDE**：Cursor 专业开发者采用率已达 21.7%

### 2.3 开发者使用现状
- 51% 的专业开发者**每天使用** AI 工具
- AI 生成代码占比已达 **42%**（GitHub 平台）
- 开发者**信任度反而在下降**（从 70%+ → 60%），说明大家越来越理性

> **一句话总结**：AI 编码工具已经"回不去了"，关键不是用不用，而是**怎么用好**。

- **没有"最好"的工具，只有"最适合当前场景"的工具**

- Qoder 在**复杂多步骤任务、文档理解、仓库级分析**方面优势明显
- 日常简单补全，免费工具已足够

## 四、Qoder 深度体验分享（15 min）

### 4.1 核心能力一览

| 能力 | 说明 | 实测评价 |
|------|------|---------|
| **代码生成** | 基于 Agent/自动模式，多步骤任务自动拆解 | ⭐ 质量较高，基本无需大改 |
| **代码补全** | Tab 补全 + Next Edits（多行预测编辑） | ⭐ 实用性不错，但 VS 不支持 |
| **Quest 模式** | 独立对话窗口，可加载仓库上下文 | ⭐ 适合文档分析、复杂调研 |
| **Agent 模式** | 多 Agent 集群并行工作 | ⭐⭐⭐ 复杂任务效率翻倍 |
| **Repo Wiki** | 自动分析仓库结构，生成知识文档 | ⭐⭐⭐ 知识沉淀利器，新成员上手快 |
| **多模型选择** | 支持 DeepSeek、Claude、GPT、Qwen 等 | ⭐⭐⭐ 灵活按任务选模型，降成本 |

### 4.2 实际案例分享

#### 案例 1：Repo Wiki — 代码知识库自动生成
- 自动分析仓库结构、模块关系、核心逻辑 → 生成详细文档
- **收益**：可直接作为团队知识沉淀，新成员上手成本大幅降低
- **进阶用法**：生成的 Wiki 注入 Agent 项目记忆 → 后续任务无需重复理解上下文 → **响应更快、Token 消耗更低**

#### 案例 2：Bug 修复（日常高频场景）
- 描述问题现象 → Agent 自动定位根因 → 生成修复代码
- **收益**：从排查到修复，几十分钟缩短到几分钟，积少成多

#### 案例 3：文档分析总结 & PPT 生成
- 上传文档/链接 → 自动理解结构、提炼结论 → 生成摘要 → 甚至直接生成 PPT
- **收益**：阅读→提炼→汇报一条龙，省去手动排版，聚焦思考决策

#### 案例 4：TFS 变更集查询（定制 MCP 能力）
- 通过自定义 MCP 工具，将 TFS 变更集查询封装成 Qoder 可调用的能力
- 实现了从 TFS 提交记录查询、状态追踪到对比分析的自动化
- **收益**：团队成员无需离开 Qoder 即可完成 TFS 操作

### 4.3 版本与定价

| 版本 | 价格 | Credits | 隐私模式 | 适合场景 |
|------|------|---------|---------|---------|
| 社区版 | **免费** | 有限 | ❌ 默认共享 | 低频率试用、尝鲜 |
| Team | **99￥/用户/月** | 3,000 credits/月 | ✅ 可开启 | 团队正式使用 |

> **实测省成本的发现**：
> - 简单任务选 DeepSeek-V4-Flash 等小模型，Token 消耗显著降低
> - 探索多人可共用Team 席位，3000 credits 够 2 人非高频使用
> - 利用 Repo Wiki + 项目记忆优化上下文 → 大幅减少浪费

### 4.4 现阶段局限性（坦诚分享）

- ⚠️ **无法集成 Visual Studio**（支持 VS Code），日常工作需同时开 VS 和 Qoder
- ⚠️ **不支持 TFS 原生集成**（支持 Git），需通过 MCP 等方式桥接
- ⚠️ 生成代码需人工校验**架构合规性**，不能完全信任
- ⚠️ 个人版/社区版数据默认共享，敏感代码需注意

## 五、AI 编码协作最佳实践（10 min）

### 5.1 什么场景适合用 AI？

| 场景 | 适合度 | 说明 |
|------|-------|------|
| CRUD 代码生成 | ⭐⭐⭐ 非常推荐 | 模板化工作，AI 效率极高 |
| Bug 排查与修复 | ⭐⭐⭐ 非常推荐 | 快速定位、多方案对比 |
| 单元测试编写 | ⭐⭐⭐ 非常推荐 | 边角覆盖好，减少遗漏 |
| 代码重构 | ⭐⭐⭐ 推荐 | 配合 Repo Wiki 效果更佳 |
| 文档/注释生成 | ⭐⭐⭐ 非常推荐 | 最节省时间的场景之一 |
| 新语言/新技术学习 | ⭐⭐⭐ 非常推荐 | 交互式学习，效率远超查文档 |
| 复杂业务逻辑设计 | ⭐⭐ 辅助参考 | 需人工主导架构 |
| 生产环境部署脚本 | ⭐ 谨慎使用 | 需人工逐行审查 |
| 安全敏感代码 | ❌ 不建议 | 核心代码避免输入公有模型 |

### 5.2 高效使用技巧

1. **给 AI 足够上下文** — 把相关代码、接口文档、报错信息一并提供，质量天差地别
2. **分步骤提需求** — 复杂任务拆解成子任务，比一次全抛效果更好
3. **善用项目记忆** — 让 AI 记住项目架构、命名规范、编码约定，后续一致性大幅提升
4. **选择合适的模型** — 简单任务用小模型（更快更省），复杂任务用大模型
5. **人工审查不可少** — AI 生成的代码必须 review，和同事提交的代码同一标准

### 5.3 需要避开的坑

| 坑 | 说明 | 建议 |
|----|------|------|
| **过度信任** | AI 看起来很自信，但可能完全错误 | **永远审查 AI 输出** |
| **上下文污染** | 项目上下文过大导致 AI 注意力分散 | 善用 Repo Wiki 精炼上下文 |
| **安全泄露** | 敏感代码/密钥输入公有模型 | 区分场景，核心代码不上云 |
| **技术债累积** | AI 倾向于复制粘贴式编码 | 审查时关注代码质量和可维护性 |
| **依赖失控** | 过度依赖 AI 导致基本功退化 | 保持思考和学习，AI 辅助而非替代 |

## 六、安全与合规（5 min）

### 6.1 数据安全分级建议

| 数据类型 | 建议使用的工具级别 | 说明 |
|---------|-----------------|------|
| 开源/公共代码 | 任何工具均可 | 无风险 |
| 内部业务代码（非核心） | Team 版（开启隐私模式） | 代码不用于模型训练 |
| 核心业务/算法代码 | ❌ **不要输入公有模型** | 评估私有化部署方案 |
| 客户数据/密钥/密码 | ❌ **绝对禁止** | 明文脱敏处理后再使用 |

### 6.2 关键提醒
- Qoder Team 版支持**隐私模式**，开启后代码数据不会用于模型训练
- Pro/社区版**默认共享使用数据**，团队使用建议走 Team 版
- 即便使用了隐私模式，核心敏感代码仍需谨慎

## 八、Q&A & 讨论（预留 10 min）

### 预期大家可能会关心的问题

**Q1: AI 工具以后会是什么角色？**
> 目前AI 目前能做的是基础编码、查错、代码规整、写注释这些重复性工作。核心业务架构、逻辑设计、问题决策、业务对接依然离不开我们。工具不会完全取代人，应该在我们的指挥下工作。

**Q2: 用 AI 写的代码质量可靠吗？**
> 质量整体较高，但需要人工审查。建议把 AI 生成的代码当作"同事提交的代码"来看待，走同样的 review 流程。

**Q3: 公司会不会强制推广/拒绝？**
> 不拒绝大家使用/非强制。本次分享的目的是信息对齐和经验交流，大家可以自由选择使用方式和频率。试点阶段也是自愿参与。

> **Q4: 安全方面怎么保证？**
> 核心机密代码不上公有模型是底线。日常开发用 Team 版开启隐私模式即可满足大部分场景的安全要求。后续会在安全使用规范上进一步细化。

**Q5: 如果我用 VS 开发，Qoder/其他工具集成不了怎么办？**
> 这是目前的客观限制。解决方案：日常 VS Code + Qoder 处理辅助任务，核心编码仍在 VS。或者关注 CodeBuddy（支持 VS 集成）等替代方案。
