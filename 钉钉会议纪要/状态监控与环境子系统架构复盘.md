# 状态监控与环境子系统架构复盘
## 一、系统架构与数据流
### 1. OC主导的数据流
- OC为自研核心模块，规范UI视图模型
- 所有监控模块由OC统一获取
### 2. PDC作为中间数据中转
- PDC负责与GB获取环境类数据
- OC ← PDC ← GB构成闭环数据路径
### 3. CDC独立处理网络状态
- CDC为自研模块，负责网络连接监测
- 不依赖PDC，直接在OC本地实现
### 4. GB为外部接口采集
- GB向电子学团队提供，仅开放接口
- 不主动推送，仅响应轮询请求
## 二、系统块与资源调度
### 1. UI分块用于展示逻辑
- 网络、环境、硬盘等分为UI模块
- 高层仅为独立区块，互不干扰
### 2. 监控项直接影响资源可用性
- CDC异常导致CPU扫描资源失效
- 硬盘/低温异常影响重建速度
- 三类资源：CT扫描、Pac扫描、重建
### 3. 双向绑定可视化的优缺点
- 每个监控项记录关联的资源列表
- 每个资源记录影响它的监控项
## 三、环境子系统重点逻辑
### 1. 依赖GB的初始化状态
- 必须等待GB组件启动成功才查询子项
- GB状态码：0成功，1运行中，-1至-4失败
### 2. 轮询策略动态调整
- GB不就绪时每10秒轮询一次
- GB就绪每120秒轮询一次
### 3. UI层不受GB状态控制
- GB不就绪时仅提示“正在开机”或“失效”
- GB就绪才显示20个DB当前值
### 4. 状态更新超时检测机制
- 对比OC与GB本地时间戳计算延迟
- 超1小时不更新则提示“状态不更新”
## 四、日常运维中的环境校验
### 1. 每次扫描前主动触发环境检查
- 非定时轮询，仅用户点击“开始检查”时触发
- 校验GB初始化状态与20个DB项
### 2. 分级提示与可控控制
- GB未就绪：禁止扫描，提示等待
- 任一DB异常：提示“温度/湿度”，仍允许扫描
- 神电/保护关机：强制终止扫描
- 环境状态欠佳：弹窗询问是否暂缓
## 五、多机型配置差异
### 1. 硬件版本对应文件tag区分
- 双源机型使用tag=1，其余为tag=2
- 默认打标为tag=2，双源需手动修改
### 2. 机型功能开关核心差异
- 六大零六支无环境子系统模块
- fat与nova具备完整监控能力
- nova为功能最全版本，需做兼容
### 3. GB接口通用状态码统一
- 失败码-1至-4在所有版本中通用
- 字段存在性由硬件决定，非接口差异
## 六、异常排查与日志定位
### 1. 优先级OC服务日志
- 记录OC发送请求与GB响应时间
- 整合各子模块状态（0正常，非0异常）
### 2. 判断问题边界的特征依据
- GB超时异常 → 问题在GB链路/硬件层
- GB返回正常但UI未更新 → 问题在OC处理层
### 3. 通过时间戳定位状态异常
- 对比GB本地时间与请求时间戳计算延迟
- 历史日志可回溯半小时内状态变化
