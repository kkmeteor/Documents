# Gitea 权限配置指南

> 本文档介绍 Gitea 的权限体系与配置方法，涵盖用户管理、组织与团队管理、仓库权限管理、分支保护规则及最佳实践。适用于小型团队（10–15 人）的自托管 Git 服务器。
>
> 版本：1.0 | 适用：Gitea 1.21+

---

## 一、Gitea 权限体系概述

Gitea 提供与 GitHub/GitLab 类似的 Web 界面，支持代码托管、Issue 跟踪、Pull Request 审查、CI/CD（Gitea Actions）等功能。对于十几人规模的团队，Gitea 的权限系统能够满足日常开发协作需求，包括：

- **组织管理**：以组织（Organization）为单位组织多人协作。
- **团队分组**：在组织内划分团队，按职能或项目组授权。
- **仓库级精细权限**：控制 clone/push、Issue、PR 等单元权限。
- **分支保护**：对重要分支（main、release/*）实施强制保护。

**权限分层**：用户 → 组织 → 团队 → 仓库 → 分支，逐层细化控制。

## 二、用户管理

### 2.1 创建用户

管理员登录后，进入「管理控制台 → 用户 → 创建用户」，填写以下信息：

- **用户名**：唯一标识，建议使用英文拼音或工号。
- **邮箱**：用于通知和密码恢复。
- **密码**：初始密码，要求用户首次登录后修改。
- **是否管理员**：勾选后该用户将拥有全局管理权限。

### 2.2 用户角色说明

| 角色 | 权限范围 | 适用场景 |
|------|----------|----------|
| 普通用户 | 仅能操作自己的仓库和被授权的仓库 | 开发人员、测试人员 |
| 管理员 | 全局所有仓库、用户、组织的完全控制权 | IT 管理员、项目负责人 |

### 2.3 用户自助注册

如果希望开放自助注册，可在配置文件 **app.ini** 中设置：

```ini
[service]
DISABLE_REGISTRATION = false
REQUIRE_SIGNIN_VIEW = true ; 登录后才能查看仓库
```

**建议：** 小型团队推荐由管理员统一创建账号，关闭自助注册（`DISABLE_REGISTRATION = true`）以提高安全性。

## 三、组织与团队管理

组织（Organization）是 Gitea 中管理多人协作的核心单元。一个组织可以包含多个团队，每个团队对应不同的职能或项目组。

### 3.1 创建组织

路径：右上角「+」→ 创建组织。填写组织名称（如 `DevTeam`）和描述。创建后系统自动生成一个「所有者团队」，创建者自动成为所有者。

### 3.2 团队类型与权限

| 团队类型 | 权限说明 | 典型用途 |
|----------|----------|----------|
| **所有者团队** | 最高权限，可管理组织设置、所有仓库、所有团队。不可删除，至少保留一名成员。 | 技术负责人、CTO |
| **管理团队** | 对指定仓库拥有完整操作权，可创建新团队。 | 项目组长、Tech Lead |
| **普通团队** | 按单元（Unit）精细授权，可指定仓库范围，可限制是否能创建新仓库。 | 开发组、测试组、外包团队 |

### 3.3 团队权限精细配置（单元级别）

普通团队支持按「单元」分配权限。每个单元可独立设置「读取」「写入」或「管理员」级别：

| 单元 | 读取 | 写入 | 管理员 | 说明 |
|------|------|------|--------|------|
| 代码 | ✓ | ✓ | ✓ | 控制 clone/push 权限 |
| Issues | ✓ | ✓ | ✓ | 控制 Issue 查看/创建/管理 |
| Pull Requests | ✓ | ✓ | ✓ | 控制 PR 查看/提交/合并 |
| Releases | ✓ | ✓ | ✓ | 控制发布版本管理 |
| Wiki | ✓ | ✓ | ✓ | 控制 Wiki 查看/编辑 |

### 3.4 推荐的团队结构示例

以下是一个典型的小型团队组织结构配置：

- **组织：** DevTeam
  - **所有者团队：** 技术负责人（1-2 人）
  - **管理团队 - ProjectAdmins：** 项目组长（2-3 人）
  - **普通团队 - Developers：** 开发人员，代码单元读写、PR 单元读写
  - **普通团队 - Testers：** 测试人员，代码单元只读、Issues 和 PR 单元读写
  - **普通团队 - Viewers：** 外部协作方，所有单元只读

## 四、仓库权限管理

### 4.1 仓库可见性

- **私有（Private）**：仅组织成员和明确授权的协作者可见。
- **内部（Internal）**：所有已登录用户可见，适合全公司共享的工具库。
- **公开（Public）**：任何人可见，适合开源项目。

### 4.2 个人仓库协作者

对于不属于组织的个人仓库，创建者可以在「仓库设置 → 协作者」中添加用户并分配权限：

- **读取（Read）**：只能 clone 和查看。
- **写入（Write）**：可以 push 代码（受分支保护规则约束）。
- **管理员（Admin）**：可修改仓库设置，但不能删除或转移仓库。

## 五、分支保护规则

分支保护是确保代码质量的重要手段。路径：仓库设置 → 分支保护 → 添加规则。

### 5.1 建议的保护规则

| 保护项 | 说明 | 适用分支 |
|--------|------|----------|
| 禁止强制 Push | 防止 `git push --force` 覆盖历史记录 | main、release/* |
| 要求 Pull Request | 禁止直接 push，必须通过 PR 合并 | main |
| 审批人数 | 设置 PR 合并所需的最少审批人数（如 1） | main |
| 禁止删除分支 | 防止误删重要分支 | main、release/* |
| CI 检查通过 | 合并前必须通过自动化测试 | main |

---

## 六、权限配置最佳实践

- **最小权限原则**：默认给只读权限，按需开放写入权限。
- **分组管理**：通过组织和团队管理权限，避免逐个仓库手动配置。
- **保护主分支**：对 main 分支启用分支保护，禁止强制 push 和直接提交。
- **关闭自助注册**：由管理员统一创建账号，防止未授权用户进入。
- **启用两步验证**：在 app.ini 中开启 2FA 支持，提高账号安全性。

> **提示：** 如团队已有 AD 域控，可集成 LDAP 实现统一账号登录（详见《Gitea LDAP 集成配置指南》），并利用 LDAP 组自动映射管理员权限。
