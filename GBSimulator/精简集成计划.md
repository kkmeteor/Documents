# GBSimulator 动态床位精简集成计划

## Context

GBSimulator 原生固定支持6个床位，现需支持根据参数动态加载任意数量的床位信息和 listmode 数据，以及按预设规则加载预置数据。用户已实现了一版代码（约15+新文件），但存在架构过度设计且未完成集成的问题。本计划执行精简 + 集成：删除冗余文件，保留核心逻辑，修改现有文件完成功能闭环。

## 核心改动思路

**精简原则：**
- 规则引擎（7个文件）→ 替换为 ViewModel 内的一个 `switch` 方法
- 配置加载器（3个文件，含接口/工厂/管理器）→ 替换为 DynamicBedViewModel 内的直接的 JSON 序列化方法
- 适配器层（2个文件）→ 直接在 GBSimulatorViewModel 中使用 DynamicBedViewModel，删掉适配器
- 保留的核心文件：BedConfiguration、BedViewModel、DynamicBedViewModel、DynamicBedControl

## Phase 3: 集成到现有代码

### 3.1 `GBSimulatorViewModel.cs` 修改

这是最关键的修改，将整个 ViewModel 从固定6床位改为动态床位。

**删除的成员：**
```csharp
// 删除
private ObservableCollection<string> listModeDataFilePath;  // 替换为 DynamicBedVm.Beds
public ObservableCollection<bool> ControlDisabled;           // 替换为 per-bed IsEnabled
private static int userControlBedNumber;                     // 替换为 DynamicBedVm.BedCount - 1
```

**新增的成员和属性映射：**
```csharp
private DynamicBedViewModel dynamicBedVm;
public DynamicBedViewModel DynamicBedVm { get; set; }

// 兼容属性（保持对外接口不变）
public ObservableCollection<string> ListModeDataFilePath  // getter 从 Beds 生成
public ObservableCollection<bool> ControlDisabled          // getter 从 Beds.IsEnabled 生成  
public int UserControlBedNumber => DynamicBedVm.BedCount - 1;
```

**修改的方法：**
- `ApplyEntryParam()` - 新增对 `DynamicBedCount`、`ConfigurationFile`、`PresetScenario` 等参数的处理
- `SelectBedPosition_ListModeFilePath()` - 改为从 DynamicBedVm 读取/写入
- `SendSameFileForAllBed()` - 改用 `DynamicBedVm.SetAllBedsToSameFile()`
- `AddNewBP()` / `DeleteLastBP()` - 改用 `DynamicBedVm.AddBedCommand` / `RemoveBedCommand`
- `MainTest()` - 验证逻辑改用 `DynamicBedVm.Beds`
- `ReadandSendListModeDataFile()` - 文件路径从 `DynamicBedVm.Beds[i].FilePath` 取
- `StartScan()` - 床位计数用 `DynamicBedVm.BedCount`
- `GetPromptRateRange()` / `GetCrystalSinglesRange()` / `GetHslSinglesCount()` - 已经是按 bed 参数动态计算，无需改动

**新增预设方法（简化替代规则引擎）：**
```csharp
private void ApplyPresetBeds(string patientType, string scanType)
{
    var key = $"{patientType?.ToLower()}_{scanType?.ToLower()}";
    switch (key)
    {
        case "adult_wholebody":
            DynamicBedVm.LoadPreset("AdultWholeBody", 6, new[]{"Head","Neck","Chest","Abdomen","Pelvis","Legs"}); break;
        case "adult_cardiac":
            DynamicBedVm.LoadPreset("AdultCardiac", 1, new[]{"Cardiac"}); break;
        case "adult_brain":
            DynamicBedVm.LoadPreset("AdultBrain", 1, new[]{"Brain"}); break;
        case "pediatric_wholebody":
            DynamicBedVm.LoadPreset("Pediatric", 4, new[]{"Head","Chest","Abdomen","Pelvis"}); break;
        case "phantom":
            DynamicBedVm.LoadPreset("Phantom", 1, new[]{"Phantom"}); break;
        default:
            int count = entryParams.DynamicBedCount ?? 6;
            DynamicBedVm.LoadPreset("Default", count); break;
    }
}
```

**命令行参数 `ApplyEntryParam` 扩展逻辑：**
```
1. 如果有 ConfigurationFile → LoadFromJsonFile
2. 否则如果有 RuleName / PatientType+ScanType → ApplyPresetBeds
3. 否则如果有 DynamicBedCount → 按数量生成默认床位
4. 否则用默认6床位
5. 最后 Apply 文件路径 (BedPositionFiles) 到对应的床位
6. 最后 Apply 其他参数 (ExpectedSpeed, AutoLaunch, WindowVisible)
```

## Phase 4: 预设数据文件支持

### `DynamicBedViewModel.LoadPreset()` 方法

```csharp
public void LoadPreset(string presetName, int bedCount, string[] bedNames = null)
{
    Beds.Clear();
    for (int i = 0; i < bedCount; i++)
    {
        var name = bedNames != null && i < bedNames.Length ? bedNames[i] : $"BedPosition{i + 1}";
        Beds.Add(new BedViewModel { Id = i + 1, Name = name, IsEnabled = true });
    }
    SelectedBedIndex = 0;
}
```

### JSON配置文件格式（简化版）

```json
{
  "bedCount": 8,
  "beds": [
    {"id":1, "name":"Head", "filePath":"head.lm", "type":"Head", "isEnabled":true},
    {"id":2, "name":"Chest", "filePath":"chest.lm", "type":"Chest", "isEnabled":true}
  ]
}
```

## 验证步骤

1. 编译项目：`msbuild Sinogram.Pet.Acquisition.GBSimulator.csproj /p:Configuration=Debug`
2. 测试默认6床位：启动无参数 → UI 显示6个床位，可添加/删除
3. 测试动态床位：`GBSimulator.exe DynamicBedCount=3` → UI 显示3个床位
4. 测试预设规则：`GBSimulator.exe PatientType=Adult ScanType=Cardiac` → UI 显示1个 Cardiac 床位
5. 测试 JSON 配置：`GBSimulator.exe ConfigurationFile=config.json` → UI 按文件加载
6. 测试文件选择流程：点击 Select file → 选择 .lm 文件 → 开始扫描
7. 测试扫描流程：Open channels → 扫描数据发送正常
