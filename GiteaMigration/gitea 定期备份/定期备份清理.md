# 当前设置为每天备份，清理三天之前的备份

## 需求变更说明
1. 执行时间：**每天 19:00 执行备份**
2. 清理规则：自动删除 **3天之前** 的备份文件
3. 推荐使用【Shell脚本方案】方便维护，下面给完整可直接复制操作步骤

# 方案：Shell脚本（推荐）
## 1、创建/更新脚本 `/opt/gitea_backup.sh`
打开脚本编辑
```bash
sudo nano /opt/gitea_backup.sh
```
替换为下面完整内容：
```bash
#!/bin/bash
DATE=$(date +%Y%m%d)
BACKUP_NAME="gitea-daily-backup-${DATE}.zip"
# 容器内路径 /data/gitea/xxx.zip，落地宿主机 /data/gitea/gitea/xxx.zip
IN_CONTAINER_PATH="/data/gitea/${BACKUP_NAME}"

# 执行Gitea全量dump备份
/usr/bin/docker exec -u git gitea gitea dump -c /data/gitea/conf/app.ini --skip-repository=false -f "${IN_CONTAINER_PATH}"

# 清理宿主机目录内 超过3天的备份压缩包
find /data/gitea/gitea -maxdepth 1 -name "gitea-daily-backup-*.zip" -mtime +3 -delete
```
> 保存退出：`Ctrl+O` →回车 →`Ctrl+X`

## 2、先手动测试脚本（必须测试！）
```bash
sudo bash /opt/gitea_backup.sh
```
执行完毕查看 `/data/gitea/` 是否生成备份文件，确认无报错。

## 3、修改定时任务（每天19点执行）
打开root定时任务
```bash
sudo crontab -e
```
把原有内容替换为这一行：
每天19点执行我们上面新增的/opt/gitea_backup.sh文件，并且输出log到/var/log/gitea-backup.log
```cron
0 19 * * * /opt/gitea_backup.sh >> /var/log/gitea-backup.log 2>&1
```
### cron表达式解释
`0 19 * * *`
- 0分 19点，**每一天**执行


---

## ⚠️重要避坑要点
1. **文件名前缀统一**
脚本与定时任务全部使用 `gitea-daily-backup-*.zip`
不要混用 `weekly / daily` 前缀，否则find清理命令匹配不到文件，清理失效！

2. `-mtime +3` 含义
文件**超过3整天**才删除
举例：今天8.11生成的备份，8.15凌晨后才会被清理，最多同时保留4份备份（今日、昨日、前天、3天前）

3. 查看定时任务确认
```bash
sudo crontab -l
```
4. 实时观察备份日志
```bash
tail -f /var/log/gitea-backup.log
```

## 💡额外提醒
每天全量备份仓库，如果仓库数量很大，压缩包会持续占用大量磁盘，持续关注磁盘空间使用率！
