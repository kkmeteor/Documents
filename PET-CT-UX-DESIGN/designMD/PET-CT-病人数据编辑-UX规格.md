# UX Specification: PET-CT 病人数据编辑 — 双重确认与审计追踪

## Pass 1: Mental Model

**Primary user intent:** 操作员在修改已完成的PET-CT检查病人数据时，需要系统自动创建数据副本并记录完整的变更历史，确保任何修改都可追溯、可审计，防止误操作导致原始数据丢失。

**Likely misconceptions:**

- **误以为"编辑"直接覆盖原数据** — 用户习惯直接修改后保存，不理解系统会生成新病人ID并保留原始记录。需要明确传达"修改=创建新版本"的模型。
- **误以为"双重确认"只是普通弹窗** — 用户可能将确认提示视为可跳过的干扰，不理解这是审计合规的强制环节。
- **混淆"病人序号"和"记录号"** — 当前界面中病人序号(E202606261228)是系统生成的，记录号为空。修改后新ID的生成规则需要清晰。
- **认为审计日志是IT部门的事** — 操作员可能不理解为何要记录修改前后的值，需要让其明白这是保护操作者自身的证据链。

**UX principle to reinforce/correct:** "数据修改不是覆盖，而是版本演进"——每次编辑产生一个新版本，原始数据永远可回溯。系统通过自动生成新ID、强制双重确认、完整审计日志三个机制共同保障数据完整性。

## Pass 2: Information Architecture

**All user-visible concepts:**

- 病人基本信息（姓名、性别、出生日期、年龄、身高、体重）
- 检查标识（病人序号、记录号）
- 检查元数据（检查时间、开单医生、操作人员、检查描述）
- 示踪剂信息（核素、示踪剂名称、满针/注射/空针时间与剂量）
- 变更摘要（修改前值 vs 修改后值的对比）
- 双重确认提示（确认修改意图 + 确认变更内容）
- 审计日志条目（谁、何时、改了什么、从什么改到什么）
- 变更历史列表（该病人所有历史版本的时间线）
- 版本关联关系（原始ID → 新ID的链接）
- 新病人ID（系统自动生成的变更版本号）

**Grouped structure:**

### 编辑主界面（当前表单层）

- 病人基本信息字段: Primary — 核心编辑对象
- 检查标识字段: Primary — 修改后自动生成新ID
- 检查元数据字段: Primary — 操作上下文
- 示踪剂信息字段: Primary — 核心编辑对象

### 变更确认层（编辑与保存之间）

- 变更差异对比（Before/After）: Primary — 双重确认的核心内容
- 确认操作按钮: Primary — 用户必须显式确认

### 审计与历史层（独立查看入口）

- 变更历史时间线: Secondary — 从病人详情页或列表页进入
- 单条审计记录详情: Secondary — 包含完整修改前后值
- 版本关联图谱: Hidden — 高级用户查看ID关联关系

### 系统反馈层

- 保存成功提示: Primary
- 新ID生成通知: Primary
- 操作审计记录自动写入: Hidden — 系统后台行为，但需在确认层告知用户

## Pass 3: Affordances

| Action | Visual/Interaction Signal |
|--------|--------------------------|
| 点击"编辑"进入修改模式 | 数据浏览界面的"编辑"按钮，标准主操作按钮样式 |
| 修改表单字段 | 输入框/下拉框获得焦点时边框高亮，修改过的字段左侧显示橙色标记条 |
| 查看变更对比 | 保存前自动弹出差异对比面板，修改字段以红色(删除)/绿色(新增)高亮显示 |
| 第一次确认（意图确认） | 模态对话框，标题明确"确认修改"，列出变更摘要，"确认修改"按钮为蓝色主按钮 |
| 第二次确认（内容确认） | 在第一次确认后，展示完整Before/After对比表，"最终确认保存"按钮 |
| 保存成功 | 绿色Toast提示"保存成功，新病人序号：E202606261228-V1" |
| 查看变更历史 | 病人详情页的"变更历史"标签页/链接，带时钟图标 |
| 查看审计详情 | 历史列表中每条记录可展开或点击进入详情面板 |
| 新ID关联原始数据 | 审计记录中原始ID和新ID均为可点击链接，点击跳转到对应版本 |
| 取消编辑 | "取消"按钮，灰色次要按钮，点击后如有未保存修改弹出丢弃确认 |

**Affordance rules:**

- 如果字段被修改过，用户应能立即看到该字段有视觉标记（橙色左边框），无需猜测哪些字段变了
- 如果用户点击保存，系统不应直接保存，而是先展示变更对比——用户应预期到"保存=先确认再保存"
- 如果用户看到红色/绿色高亮的对比表，应理解红色=原值、绿色=新值
- 如果用户看到"V1"后缀的病人序号，应理解这是原始数据的修改版本
- 如果用户点击审计记录中的ID链接，应能跳转到对应版本的数据

## Pass 4: Cognitive Load

**Friction points:**

| Moment | Type | Simplification |
|--------|------|----------------|
| 修改多个字段后点保存 | Choice — 用户不确定哪些字段变了 | 自动高亮已修改字段，变更对比表只展示有变化的字段，未修改字段不显示 |
| 双重确认的流程 | Uncertainty — 为什么要确认两次？ | 第一次确认聚焦"意图"（你确定要修改这个病人的数据吗？），第二次确认聚焦"内容"（请核对以下变更），文案明确区分两层含义 |
| 新病人ID的含义 | Uncertainty — 为什么产生了新ID？ | 保存成功后Toast中明确说明"已创建新版本 E202606261228-V1，原始数据 E202606261228 保持不变" |
| 审计日志在哪里查看 | Uncertainty — 修改后去哪看记录？ | 保存成功Toast中带"查看变更历史"链接，一键跳转 |
| 修改已完成检查 vs 未完成检查 | Choice — 不同状态操作不同 | 系统自动判断：已完成的检查强制双重确认，未完成的检查可简化为单次确认（配置项） |
| 大量字段变更时的对比表 | Waiting/Overwhelm — 信息过多 | 按字段分组展示（病人信息组、示踪剂组），支持折叠/展开 |

**Defaults introduced:**

- 默认只展示有变化的字段：减少认知负担，用户不需要在完整表单中找差异
- 默认展开变更摘要（第一次确认）：用户必须先看到改了什麼才能确认
- 默认新ID格式为 `{原ID}-V{n}`：直观表达版本关系，无需额外解释
- 审计日志默认按时间倒序：最近修改在最上面，符合用户查看习惯

## Pass 5: State Design

### 编辑表单界面

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | 不适用（编辑必须从已有数据进入） | — | — |
| Loading | 表单字段显示骨架屏或loading spinner | 数据正在加载 | 等待或取消 |
| Success | 所有字段正常显示，可编辑 | 数据已就绪 | 修改任意字段、取消 |
| Partial | 部分字段有值，部分为空（如记录号） | 某些信息尚未填写 | 填写缺失字段或保存 |
| Error | 字段校验失败时红色边框+错误提示 | 该字段输入不合法 | 修正输入 |
| Modified | 已修改字段左侧显示橙色标记条 | 这些字段已被改动 | 继续修改、保存、取消 |

### 第一次确认对话框（意图确认）

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | 不适用 | — | — |
| Loading | 不适用（数据已在表单中） | — | — |
| Success | 变更摘要列表（仅显示修改的字段名和新值） | 我改了这些内容 | 确认进入第二步、返回修改、取消 |
| Partial | 不适用 | — | — |
| Error | 不适用 | — | — |

### 第二次确认对话框（内容确认）

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | 不适用 | — | — |
| Loading | 不适用 | — | — |
| Success | 完整Before/After对比表，红色=原值，绿色=新值 | 这是完整的变更内容，核对无误后可最终保存 | 最终确认保存、返回修改、取消 |
| Partial | 不适用 | — | — |
| Error | 保存失败提示+错误原因 | 保存遇到问题 | 重试、返回修改 |

### 保存结果反馈

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | 不适用 | — | — |
| Loading | 保存按钮显示loading spinner，按钮禁用 | 系统正在保存 | 等待 |
| Success | 绿色Toast："保存成功，新版本 E202606261228-V1 已创建" + "查看变更历史"链接 | 修改已生效，原始数据保留 | 关闭Toast、点击链接查看历史、继续操作 |
| Partial | 不适用 | — | — |
| Error | 红色Toast："保存失败：{错误原因}" | 保存未成功，数据未改变 | 重试、返回修改 |

### 变更历史列表

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | "暂无变更记录"空状态图标+文字 | 该病人数据从未被修改过 | 返回 |
| Loading | 列表区域显示loading spinner | 历史记录正在加载 | 等待 |
| Success | 时间线列表，每条显示：时间、操作人、变更摘要、版本ID | 这是该病人的所有修改记录 | 点击展开详情、点击ID跳转版本 |
| Partial | 不适用 | — | — |
| Error | 错误提示+重试按钮 | 历史记录加载失败 | 重试、返回 |

### 审计记录详情

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | 不适用 | — | — |
| Loading | 详情面板loading | 详情正在加载 | 等待 |
| Success | 完整信息：操作人、操作时间、原始ID、新ID、每个字段的Before/After值 | 这是该次修改的完整审计记录 | 关闭详情、点击ID跳转 |
| Partial | 不适用 | — | — |
| Error | 加载失败提示 | 详情无法获取 | 重试、关闭 |

## Pass 6: Flow Integrity

**Flow risks:**

| Risk | Where | Mitigation |
|------|-------|------------|
| 用户修改后直接点保存，不理解会产生新ID | 编辑表单→保存 | 第一次确认对话框明确告知"此操作将创建新版本，原始数据保持不变" |
| 用户连续快速点击两次确认 | 双重确认流程 | 第一次确认后按钮立即禁用，防止重复提交 |
| 用户修改了很多字段但只记得改了哪几个 | 变更对比表 | 只展示有变化的字段，按分组排列，一目了然 |
| 用户在审计日志中迷失，找不到原始数据 | 变更历史→详情 | 每条记录显示版本链（原始ID → V1 → V2），每个ID可点击跳转 |
| 用户取消编辑后不确定数据是否被改动 | 取消操作 | 取消时如有修改，弹出"放弃未保存的修改？"确认；取消后数据浏览界面不变 |
| 网络异常导致保存失败但审计日志已写入 | 保存过程 | 保存采用事务机制：审计日志与数据写入同一事务，失败则全部回滚 |
| 用户不理解V1/V2版本号的含义 | 新ID生成 | Toast和审计记录中均用"版本1"、"版本2"中文辅助说明 |

**Visibility decisions:**

- Must be visible: 已修改字段的标记、变更对比表、双重确认对话框、保存成功后的新ID、审计日志入口
- Can be implied: 审计日志的自动写入过程（只需在确认时告知"本次修改将被记录"）、版本关联的数据库实现细节

**UX constraints:**

- 双重确认不可跳过或配置关闭（合规要求）
- 审计日志不可删除或修改（合规要求）
- 原始数据不可被覆盖或删除（数据完整性）
- 新病人ID必须由系统自动生成，不允许手动输入
- 已完成检查的修改必须走完整双重确认流程

## Visual Specifications

### 整体布局

基于现有编辑弹窗（Modal Dialog）进行扩展，不改变主框架布局。新增的变更确认层以嵌套模态框（Nested Modal）形式叠加在编辑弹窗之上。变更历史作为独立页面/标签页存在。

### 屏幕1：编辑表单（修改态）

**布局：** 与现有界面保持一致（病人信息两列布局 + 示踪剂信息两列布局 + 底部保存/取消按钮）

**新增视觉元素：**

- **已修改字段标记：** 被修改的输入框左侧显示3px宽的橙色竖条（`#F59E0B`），输入框边框变为橙色
- **底部状态栏：** 在保存/取消按钮上方新增一行灰色小字："已修改 3 个字段"（动态计数）
- **保存按钮文案变更：** 从"保存"变为"保存并确认"，暗示非直接保存

### 屏幕2：第一次确认 — 意图确认对话框

**类型：** 模态对话框（Modal），宽度480px，居中显示

**内容结构：**

```
┌─────────────────────────────────────┐
│   确认修改病人数据                    │
│                                     │
│  您即将修改以下病人数据，系统将自动     │
│  创建新版本，原始数据将保持不变。        │
│                                     │
│  病人序号：E202606261228              │
│  病人姓名：XXX002                     │
│  检查时间：2026/6/26 12:28            │
│                                     │
│  修改内容摘要（3项）：                  │
│  · 身高：1 cm → 165 cm               │
│  · 体重：1 kg → 55 kg                │
│  · 血糖：→ 5.6 mmol/L                │
│                                     │
│  本次修改将被完整记录到审计日志中。       │
│                                     │
│         [取消]    [确认，继续核对 →]    │
└─────────────────────────────────────┘
```

**视觉规范：**

- 背景遮罩：`rgba(0,0,0,0.45)`
- 对话框背景：白色 `#FFFFFF`，圆角8px，阴影 `0 4px 16px rgba(0,0,0,0.12)`
- 标题：16px，`#1F2937`，加粗，带黄色警告图标
- 说明文字：14px，`#6B7280`
- 病人信息行：13px，`#374151`，浅灰背景块 `#F9FAFB`，圆角4px，padding 8px 12px
- 变更摘要列表：14px，修改前值 `#EF4444`（红色），箭头 `#9CA3AF`，修改后值 `#10B981`（绿色）
- 审计提示文字：12px，`#9CA3AF`，带锁图标
- 取消按钮：灰色边框，`#6B7280` 文字
- 确认按钮：蓝色 `#3B82F6`，白色文字

### 屏幕3：第二次确认 — 内容核对对话框

**类型：** 模态对话框（Modal），宽度640px（比第一次更宽以容纳对比表），居中显示

**内容结构：**

```
┌──────────────────────────────────────────────────┐
│   核对变更内容                                    │
│                                                  │
│  请仔细核对以下变更，确认无误后点击"最终确认保存"。    │
│                                                  │
│  ┌────────────────────────────────────────────┐  │
│  │ 字段        │ 修改前        │ 修改后         │  │
│  ├────────────────────────────────────────────┤  │
│  │ 身高        │ 1 cm         │ 165 cm  ▲     │  │
│  │ 体重        │ 1 kg         │ 55 kg   ▲     │  │
│  │ 血糖        │ —            │ 5.6 mmol/L ▲ │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│  新版本号：E202606261228-V1（版本1）               │
│                                                  │
│     [返回修改]          [最终确认保存 ✓]            │
└──────────────────────────────────────────────────┘
```

**视觉规范：**

- 表格样式：
  - 表头：13px，`#6B7280`，背景 `#F3F4F6`，下边框 `#E5E7EB`
  - 数据行：14px，交替行背景 `#FFFFFF` / `#F9FAFB`
  - 修改前值列：`#EF4444`（红色），删除线样式可选
  - 修改后值列：`#10B981`（绿色），加粗
  - 变更方向指示：绿色上箭头 `▲` 表示新增/增大
- 新版本号提示：13px，`#3B82F6`（蓝色），带信息图标
- 返回修改按钮：灰色边框
- 最终确认保存按钮：绿色 `#10B981`，白色文字，带勾选图标

### 屏幕4：保存成功反馈

**类型：** Toast通知，右上角显示，3秒后自动消失（可手动关闭）

**内容结构：**

```
┌─────────────────────────────────────────┐
│  ✓  保存成功                              │
│     新版本 E202606261228-V1（版本1）已创建  │
│     原始数据 E202606261228 保持不变        │
│     [查看变更历史 →]                      │
└─────────────────────────────────────────┘
```

**视觉规范：**

- 背景：白色 `#FFFFFF`，左侧4px绿色竖条 `#10B981`
- 阴影：`0 4px 12px rgba(0,0,0,0.1)`
- 圆角：6px
- 标题：14px，`#1F2937`，加粗
- 说明文字：13px，`#6B7280`
- 链接：13px，`#3B82F6`，下划线，hover加深
