# UX Specification: PET-CT 检查序列移动 — 双重确认与审计追踪

## Pass 1: Mental Model

**Primary user intent:** 操作员在将DICOM检查序列从一个病人移动到另一个病人时，需要系统强制双重确认并记录完整审计日志，确保每次移动都可追溯到"谁在何时将什么序列从哪个病人移到了哪个病人"，防止非法的数据归属篡改。

**Likely misconceptions:**

- **误以为"移动"只是简单的文件转移** — 用户可能不理解移动检查序列本质上是改变了DICOM数据的病人归属，这在医疗合规中是敏感操作。需要明确传达"移动=改变数据归属关系"的模型。
- **误以为已有确认弹窗就够了** — 当前系统有2次确认但没有审计日志，用户可能认为"点了确定就完事了"。需要让用户理解审计日志是保护操作者自身的证据链。
- **误选目标病人** — 搜索"2026"可能返回多条结果，用户可能选错行。需要让目标病人的选择过程更加明确和可核对。
- **不理解移动的不可逆性** — 用户可能以为移动后可以轻松撤销。需要明确告知移动操作的严肃性。

**UX principle to reinforce/correct:** "检查序列移动不是文件搬家，而是医疗数据归属变更"——每次移动改变DICOM数据的病人关联关系，必须经过意图确认+内容核对双重关卡，并自动写入不可篡改的审计日志。

---

## Pass 2: Information Architecture

**All user-visible concepts:**

- 当前检查信息（病人姓名、病人序号、出生日期、性别、年龄、身高、体重、检查时间）
- 当前病人体位
- 当前示踪剂信息（核素、示踪剂、满针/空针/注射时间与剂量、注射日期）
- 目标病人搜索条件（病人序号、病人姓名）
- 目标病人搜索结果列表（病人序号、病人姓名、性别、出生日期）
- 目标病人的检查列表（仅供参考）
- 被移动的检查序列名称（如PETCT_Mine_Head）
- 双重确认对话框（第1次：意图确认 + 第2次：内容核对）
- 审计日志条目（操作人、操作时间、源病人、目标病人、检查序列名）
- 移动操作记录（审计日志查看入口）

**Grouped structure:**

### 移动主界面（当前弹窗层）

- 当前检查信息（病人信息+体位+示踪剂）: Primary — 明确"从哪来"
- 目标病人搜索与选择: Primary — 明确"到哪去"
- 目标病人检查列表: Secondary — 辅助确认目标病人是否正确
- 移动按钮: Primary — 触发双重确认流程

### 确认层（移动按钮之后）

- 第一次确认（意图确认）: Primary — 确认移动意图，展示源→目标摘要
- 第二次确认（内容核对）: Primary — 完整核对移动详情，包含审计日志告知

### 审计层（独立查看入口）

- 移动审计日志列表: Secondary — 从数据浏览界面进入
- 单条审计记录详情: Secondary — 完整移动信息

### 系统反馈层

- 移动成功提示: Primary
- 审计日志自动写入通知: Hidden — 系统后台行为，在确认层告知

## Pass 3: Affordances

| Action | Visual/Interaction Signal |
|--------|--------------------------|
| 打开移动对话框 | 数据浏览界面的"移动"按钮，标准主操作按钮样式 |
| 搜索目标病人 | 输入病人序号/姓名后点击"搜索"按钮，结果列表刷新 |
| 选择目标病人 | 点击搜索结果行，该行高亮（蓝色背景），表示已选中 |
| 查看目标病人检查列表 | 选中目标病人后，下方自动显示该病人的检查列表（仅供参考） |
| 点击"移动" | 不直接执行，弹出第一次确认对话框 |
| 第一次确认（意图确认） | 模态对话框，标题"确认移动检查序列"，红色警告图标，显示源病人→目标病人摘要 |
| 第二次确认（内容核对） | 更宽的模态对话框，完整Before/After对比，明确审计日志告知 |
| 移动成功 | 绿色Toast提示"移动成功" + 审计记录信息 + "查看审计日志"链接 |
| 查看审计日志 | 数据浏览界面的"审计日志"入口，带盾牌图标 |
| 取消移动 | 任何阶段的"取消"按钮，灰色次要按钮，返回上一步 |

**Affordance rules:**

- 如果搜索结果行被选中，用户应能立即看到蓝色高亮，明确知道目标病人是谁
- 如果用户点击"移动"，系统不应直接移动，而是先弹出确认——用户应预期到"移动=先确认再执行"
- 如果用户看到红色警告图标，应理解这是一个不可轻易撤销的敏感操作
- 如果用户看到审计日志告知，应理解本次移动将被永久记录
- 如果目标病人未选中，"移动"按钮应处于禁用状态

## Pass 4: Cognitive Load

**Friction points:**

| Moment | Type | Simplification |
|--------|------|----------------|
| 搜索结果有多条相似记录 | Choice — 可能选错目标病人 | 选中行蓝色高亮+下方显示该病人检查列表作为二次核对；搜索框支持序号和姓名双条件 |
| 不理解移动的后果 | Uncertainty — 不知道移动意味着什么 | 第一次确认明确告知"此操作将改变检查序列的病人归属，原始病人将不再拥有此序列" |
| 为什么要确认两次 | Uncertainty — 觉得麻烦 | 第一次聚焦"意图"（确认源→目标），第二次聚焦"内容"（完整详情+审计告知），文案区分两层含义 |
| 移动后去哪看记录 | Uncertainty — 不知道审计日志在哪 | 移动成功Toast中带"查看审计日志"链接，一键跳转 |
| 不确定是否选对了目标病人 | Uncertainty | 选中后下方展示目标病人的检查列表，用户可通过检查历史辅助判断是否为目标病人 |
| 移动按钮在目标未选中时可用 | Choice — 可能误触 | 目标病人未选中时"移动"按钮禁用（灰色），选中后变为可用（蓝色） |

**Defaults introduced:**

- 默认"移动"按钮禁用直到选中目标病人：防止误操作
- 默认选中目标病人后展示其检查列表：辅助用户二次确认
- 审计日志默认按时间倒序：最近操作在最上面
- 搜索默认为空，不自动搜索：避免加载无关数据

## Pass 5: State Design

### 移动主界面

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | 不适用（必须从已有检查进入） | — | — |
| Loading | 搜索结果显示loading spinner | 正在搜索目标病人 | 等待或修改搜索条件 |
| Success | 搜索结果列表+选中行高亮+下方检查列表 | 已找到目标病人并可核对 | 选择其他病人、点击移动、取消 |
| Partial | 搜索结果为空 | 未找到匹配的病人 | 修改搜索条件、取消 |
| Error | 搜索失败提示 | 搜索遇到问题 | 重试、取消 |
| NoSelection | 搜索结果有但无选中行，"移动"按钮灰色禁用 | 尚未选择目标病人 | 点击选择一行、取消 |

### 第一次确认对话框（意图确认）

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Success | 红色警告图标+源病人→目标病人摘要+检查序列名 | 我即将把这个序列从这个病人移到那个病人 | 确认进入第二步、取消 |
| Error | 不适用 | — | — |

### 第二次确认对话框（内容核对）

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Success | 完整移动详情表+审计日志告知+移动按钮 | 这是完整的移动信息，确认后将永久记录 | 最终确认移动、返回修改、取消 |
| Loading | 移动按钮显示loading spinner+禁用 | 系统正在执行移动 | 等待 |
| Error | 移动失败提示+错误原因 | 移动未成功，数据未改变 | 重试、返回 |

### 移动结果反馈

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Success | 绿色Toast："移动成功" + 审计记录信息 + "查看审计日志"链接 | 序列已成功移动，操作已记录 | 关闭Toast、点击链接查看日志 |
| Error | 红色Toast："移动失败：{原因}" | 移动未成功 | 重试、关闭 |

### 审计日志列表

| State | User Sees | User Understands | User Can Do |
|-------|-----------|-----------------|-------------|
| Empty | "暂无移动记录"空状态 | 没有检查序列移动历史 | 返回 |
| Loading | 列表区域loading spinner | 审计日志正在加载 | 等待 |
| Success | 时间线列表：时间、操作人、源病人→目标病人、检查序列名 | 这是所有移动操作的审计记录 | 点击展开详情 |
| Error | 错误提示+重试按钮 | 审计日志加载失败 | 重试、返回 |

## Pass 6: Flow Integrity

**Flow risks:**

| Risk | Where | Mitigation |
|------|-------|------------|
| 用户选错目标病人 | 搜索结果选择 | 选中行高亮+下方显示检查列表辅助核对；第二次确认再次展示完整信息 |
| 用户快速连续点击两次确认 | 双重确认流程 | 确认后按钮立即禁用+loading状态，防止重复提交 |
| 用户不理解移动的不可逆性 | 移动主界面 | 第一次确认用红色警告图标+明确文案"原始病人将不再拥有此序列" |
| 移动成功但审计日志写入失败 | 移动执行过程 | 移动与审计日志写入同一事务，失败则全部回滚 |
| 用户在审计日志中找不到某次移动记录 | 审计日志列表 | 支持按病人序号、操作人、日期范围筛选 |
| 搜索返回结果过多，用户迷失 | 搜索结果列表 | 支持双条件搜索（序号+姓名），结果列表限制显示条数 |

**Visibility decisions:**

- Must be visible: 当前检查完整信息、目标病人搜索结果与选中状态、双重确认对话框、移动成功后的审计告知、审计日志入口
- Can be implied: 审计日志的自动写入过程（在确认时告知即可）、DICOM文件实际传输的技术细节

**UX constraints:**

- 双重确认不可跳过或配置关闭（合规要求）
- 审计日志不可删除或修改（合规要求）
- 目标病人必须通过搜索选择，不允许手动输入病人序号
- 移动操作必须记录完整审计信息（源病人、目标病人、检查序列名、操作人、时间）
- 移动按钮在目标病人未选中时必须禁用

## Visual Specifications

### 整体布局

基于现有移动弹窗进行增强，保持左右分栏布局（当前检查信息 | 目标病人搜索选择）。双重确认以嵌套模态框叠加。审计日志作为独立页面。

### 颜色系统（与前一规格保持一致）

| 用途 | 色值 | 说明 |
|------|------|------|
| 主操作蓝 | `#3B82F6` | 确认按钮、链接、选中行高亮 |
| 成功绿 | `#10B981` | 移动成功、最终确认按钮 |
| 警告红 | `#EF4444` | 警告图标、危险操作提示 |
| 警告橙 | `#F59E0B` | 注意提示 |
| 文字主色 | `#1F2937` | 标题、重要文字 |
| 文字次要 | `#6B7280` | 说明文字 |
| 文字辅助 | `#9CA3AF` | 提示性文字 |
| 边框 | `#E5E7EB` | 输入框、表格边框 |
| 背景浅灰 | `#F3F4F6` | 表头、信息块背景 |
| 背景最浅 | `#F9FAFB` | 交替行、卡片背景 |
| 选中行蓝底 | `#EFF6FF` | 搜索结果选中行背景 |
| 遮罩 | `rgba(0,0,0,0.45)` | 模态框背景遮罩 |

### 屏幕1：移动主界面（增强版）

**布局：** 左右分栏，左侧当前检查信息（与现有界面一致），右侧目标病人搜索选择（增强）

**增强点：**

- **目标病人选中高亮：** 选中的搜索结果行背景变为 `#EFF6FF`，左侧显示蓝色竖条
- **移动按钮状态：** 未选中目标病人时按钮灰色禁用（`#9CA3AF`背景，不可点击）；选中后变为蓝色可用（`#3B82F6`）
- **底部审计提示：** 移动按钮上方新增一行灰色小字："移动操作将被记录到审计日志"
