# TfsTool 部署说明

## 项目架构

本项目包含3个子项目：

1. **TfsTool.Core** - 类库（被其他项目引用）
2. **TfsTool.ApiService** - .NET Framework 4.7 后端API服务（端口9000）
3. **TfsTool.Web** - .NET 8.0 Blazor Server 前端（端口5000）

## 部署步骤

### 1. 构建Release版本（在开发机上）

```powershell
# 构建后端服务
dotnet build TfsTool.ApiService/TfsTool.ApiService.csproj -c Release -o D:\PublishArtifacts\TfsTool.ApiService

# 发布前端（包含所有静态文件，包括MudBlazor）
dotnet publish TfsTool.Web/TfsTool.Web.csproj -c Release -o D:\PublishArtifacts\TfsTool.Web
```

### 2. 复制文件到测试机

将以下文件夹复制到测试机（例如 `F:\Release\`）：

```
D:\PublishArtifacts\TfsTool.ApiService   -->   F:\Release\TfsTool.ApiService
D:\PublishArtifacts\TfsTool.Web          -->   F:\Release\TfsTool.Web
start-simple.ps1                         -->   F:\Release\start-simple.ps1
stop-simple.ps1                          -->   F:\Release\stop-simple.ps1
```

### 3. 配置设置

编辑 `TfsTool.Web/appsettings.json`：

```json
{
  "TfsUrl": "http://your-tfs-server:8080/tfs/DefaultCollection",
  "TfsApiServiceUrl": "http://localhost:9000/",
  "AvailableProjects": "project1|$/path1;project2|$/path2",
  "DingTalkWebhookUrl": "https://oapi.dingtalk.com/robot/send?access_token=xxx",
  "DingTalkSecret": "SECxxx"
}
```

### 4. 启动服务

在测试机上使用PowerShell运行：

```powershell
.\start-simple.ps1
```

访问地址：
- 前端：http://localhost:5000/
- 后端：http://localhost:9000/

### 5. 停止服务

```powershell
.\stop-simple.ps1
```

## 配置项说明

| 配置项 | 说明 | 示例 |
|---------|-------------|---------|
| TfsUrl | TFS服务器地址 | http://10.10.10.63:8080/tfs/DefaultCollection |
| TfsApiServiceUrl | 后端API服务地址 | http://localhost:9000/ |
| AvailableProjects | 可用的项目列表 | 格式：显示名称\|路径;显示名称\|路径 |
| DingTalkWebhookUrl | 钉钉机器人Webhook | https://oapi.dingtalk.com/robot/send?access_token=xxx |
| DingTalkSecret | 钉钉机器人密钥 | SECxxx |

## 端口信息

| 服务 | 端口 | 说明 |
|---------|------|-------------|
| TfsTool.ApiService | 9000 | 后端API服务 |
| TfsTool.Web | 5000 | 前端Web服务 |

## 目录结构

```
部署目录/
├── start-simple.ps1           # 快速启动脚本
├── stop-simple.ps1            # 停止服务脚本
├── TfsTool.Web/               # 前端项目（publish文件夹）
│   ├── TfsTool.Web.exe
│   ├── wwwroot/               # 静态文件，包括MudBlazor
│   ├── appsettings.json
│   └── ...
├── TfsTool.ApiService/        # 后端项目
│   ├── TfsTool.ApiService.exe
│   ├── Data/                  # SQLite数据库目录
│   └── ...
└── logs/                      # 日志目录（自动创建）
```

## 重要说明

1. **必须使用 `publish` 文件夹**：前端必须使用 `dotnet publish` 的输出，而不是 `bin/Release/net8.0/`，因为publish文件夹包含所有必需的静态文件（包括MudBlazor的JS/CSS）。

2. **端口冲突**：如果端口9000或5000被占用，脚本会自动尝试关闭占用进程。

3. **数据库**：后端服务会自动在 `Data/` 目录下创建SQLite数据库文件。

4. **首次部署**：首次部署时，服务端需要连接TSF server，需要手动输入合法的用户名密码。
