# 会议纪要

### TfsTool 产品使用及操作文档

## 一、产品概述

**TfsTool 是一个用于 TFS（Team Foundation Server）变更集比较和合并管理的工具，帮助开发团队更高效地追踪代码变更、管理合并候选变更集。**

### 背景介绍&痛点分析

**在软件版本发布过程中，开发团队面临着复杂的分支管理和变更集追踪挑战。当进行版本发版时，测试团队需要准确识别并比较多个开发分支与待发版分支之间的变更集差异，同时有效管理待合并的变更集，确保其他分支中的功能更新和问题修复不会在发版分支中遗漏。**

**传统工作方式的痛点：**

1.  **效率低/风险大：需要手动复制各分支的变更集信息，操作繁琐且耗时，并且容易出错，变更集遗漏可能导致发版版本缺少重要功能或修复，影响产品质量**
    
2.  **协作困难：变更集信息分散，团队成员间难以高效同步和共享**
    
3.  **追踪困难：变更集的合并状态缺乏统一管理，无法清晰追踪处理进度**
    
4.  **沟通不畅：变更集信息无法及时自动通知相关团队成员，影响协作效率**
    

**TfsTool 解决方案：**

**TfsTool 通过提供直观易用的界面和强大的功能，帮助开发团队：**

*   **快速比较不同分支间的变更集差异**
    
*   **集中管理合并候选变更集**
    
*   **标记和追踪变更集的合并状态**
    
*   **通过钉钉等渠道高效发送合并通知**
    

**从而显著提升版本发布过程中的变更集管理效率，降低人为错误风险，确保代码变更的完整性和可追溯性。**

### 主要功能

1.  **变更集比较 - 比较两个分支之间的变更集差异**
    
2.  **合并候选管理 - 查看和管理待合并的变更集**
    
3.  **状态标记 - 标记变更集的合并状态（需合并/不合并/延迟合并）**
    
4.  **通知发送 - 发送合并通知到钉钉**
    
5.  **（规划中）自动创建TAPD任务 - 自动创建TAPD任务，便于跟踪和记录变更集信息**

## 三、功能使用说明

### 3.1 主页面

**访问** [**http://10.10.9.65:5000/**](http://10.10.9.65:5000/) **进入主页面，包含以下功能模块：**

#### 3.1.1 项目选择

*   **从下拉框选择要操作的 TFS 项目**
    
*   **系统自动加载项目配置的路径信息**
    

#### 3.1.2 分支比较

1.  **选择源分支 - 选择要合并代码的来源分支**
    
2.  **选择目标分支 - 选择要合并代码的目标分支**
    
3.  **点击"比较"按钮 - 系统加载两个分支之间的差异变更集**
    

### 3.2 变更集列表

**比较后会显示两个标签页：**

#### 3.2.1 未合并变更集

**显示源分支中尚未合并到目标分支的所有变更集，包含以下信息：**

| **字段** | **说明** |
| --- | --- |
| **状态** | **变更集的合并状态标记** |
| **变更集ID** | **TFS 变更集唯一标识** |
| **Story/BugId** | **关联的工作项ID** |
| **提交者** | **代码提交人员** |
| **Reviewer** | **代码审查人员** |
| **提交时间** | **变更集提交时间** |
| **描述** | **变更集描述信息** |

**操作功能：**

*   **筛选 - 可按提交者和状态进行筛选**
    
*   **多选 - 勾选多行进行批量操作**
    
*   **标记状态 - 选中后点击按钮标记为：**
    
    *   **需合并 - 需要合并到目标分支**
        
    *   **不合并 - 不需要合并**
        
    *   **延迟合并 - 稍后需要合并**
        

#### 3.2.2 已合并变更集

**显示已经合并到目标分支的变更集历史。由tfs服务器拉取变更集合并历史，并显示在页面中。**

#### 3.2.2 合并候选集

*   **本功能主要是为了模拟 TFS 中的变更集合并历史，方便团队成员查看和管理已合并的变更集。**
    
*   **\*\*经测试，通过TFS API获取的变更集合并历史与前端显示的变更集合并历史有差异，API获取的结果会多于前端显示的结果，需要人为筛选出已合并的变更集。**
    

### 3.3 状态说明

| **状态** | **颜色** | **说明** |
| --- | --- | --- |
| **需合并** | **绿色** | **需要合并到目标分支** |
| **不合并** | **红色** | **不需要合并** |
| **延迟合并** | **黄色** | **稍后需要合并** |
| **未标记** | **默认** | **尚未进行状态标记** |

## 四、操作规范

### 4.1 日常使用流程

1.  **定期比较分支 - 建议每隔一段时间（如每天）或每次合并前进行比较**
    
2.  **标记变更集状态 - 根据合并计划标记每个变更集**
    
3.  **发送通知 - 选中待合并的变更集发送通知给相关人员**
    
4.  **执行合并操作 - 在 TFS 中执行实际的代码合并**
    

### 4.2 状态标记规范

*   **需合并 - 确认需要合并的变更集，通常是已完成的特性或修复**
    
*   **不合并 - 明确不需要合并的变更集，如废弃的实验代码或不匹配的功能代码**
    
*   **延迟合并 - 暂时不合并但后续需要处理的变更集，例如有些change不需要立即合并，但后续需要合并**

## 五、代码合并提交规范

### 5.1 提交信息格式要求

**必须在 Merge 的提交信息中包含 Source 分支的 ChangesetId。**

#### 单变更集合并

**当合并单个变更集时，提交信息格式：**

```plaintext
Merge [分支名] to [目标分支名]

Source Changeset: 12345

[变更描述]

```

**示例：**

```plaintext
Merge nova to flight 

Source Changeset: 24086 

tengfei ma 2026/4/17 14:50:39 bug 1016495 fix: 英文状态下环境子系统相关功能界面 显示不全

```

#### 多变更集合并

**当同时合并多个变更集时，必须将所有 Source ChangesetId 以逗号分隔：**

```plaintext
Merge [分支名] to [目标分支名]

Source Changeset: 12345, 12346, 12347

[变更描述]

```

**示例：**

```plaintext
Merge nova to flight 

Source Changeset: 24086,24084 

tengfei ma 2026/4/17 14:50:39 bug 1016495 fix: 英文状态下环境子系统相关功能界面 显示不全
tengfei ma 2026/4/17 9:50:47 bug 1017458 fix: 隐藏自由心脏扫描参数界面 从床位x到床位x选项


```

### 回滚变更集

```plaintext
RollBack code:

[rollback]/[forget] for changeset 22481

[变更描述] --需要包含完整的source changeset注释信息

```

**示例：**

```plaintext
[rollback] for changeset 22481

tengfei ma 2026/4/17 14:50:39 bug 1016495 fix: 英文状态下环境子系统相关功能界面 显示不全

[forget] for changeset 22481

tengfei ma 2026/4/17 14:50:39 bug 1016495 fix: 英文状态下环境子系统相关功能界面 显示不全

```

**分支名列表：**

```plaintext
nova
flight
flight plus
其他待添加...

```

### 5.2 规范要求

1.  **必须包含 ChangesetId - 每个合并提交都必须包含源分支的 ChangesetId**
    
2.  **多变更集使用逗号分隔 - 多个 ChangesetId 之间使用英文逗号** `**,**` **分隔**
    
3.  **ChangesetId 必须准确 - 确保 ChangesetId 与 TFS 中的实际 ID 一致**
    
4.  **格式统一 - 使用 "Source Changeset:" 作为前缀**
    

### 5.3 为什么需要这个规范

1.  **可追溯性 - 通过 ChangesetId 可以快速追溯到原始变更**
    
2.  **审计需求 - 便于代码审查和合规审计**
    
3.  **问题排查 - 出现问题时可以快速定位相关变更**
    
4.  **工具集成 - 支持自动化工具解析和统计**

## 六、常见问题

### 6.1 页面加载失败

**问题： 访问页面时出现错误**

**解决：**

1.  **检查后端服务是否已启动（端口9000）**
    
2.  **检查前端服务是否已启动（端口5000）**
    
3.  **去服务器段查看程序运行日志，确认是否有异常信息**
    

### 6.2 无法连接TFS

**问题： 提示 TFS 连接失败**

**解决：**

1.  **检查** appsettings.json **中的** TfsUrl **配置**
    
2.  **确认网络可以访问 TFS 服务器**
    
3.  **确认当前用户有 TFS 访问权限**
    
4.  **首次部署时，服务端需要连接TSF server，需要在服务器手动输入合法的用户名密码。**
    

### 6.3 变更集状态未保存

**问题： 标记状态后刷新页面丢失**

**解决：**

1.  **检查后端服务文件夹的** Data **目录是否有写入权限**
    
2.  **查看后端日志确认是否有数据库错误**
