## 一、整体系统架构

### 1.1 三层架构总览

整个 PET-CT 采集系统采用分层设计，从上到下分为三层：

```
┌─────────────────────────────────────────────────────────────────┐
│                     Console Application                         │
│  ┌───────────────── ┐   ┌─────────────────┐                     │
│  │ScanProcessConsole│   │  PetScanManager │                     │
│  │   ViewModel      │──→│   (BizLogic)    │                     │
│  │   .StartScan()   │   │  .StartScan()   │                     │
│  └──────────────── ─┘   └────────┬────────┘                     │
└──────────────────────────────────┼──────────────────────────────┘
                                   │
                                   ↓ WCF (HTTP, 端口 8080)
┌─────────────────────────────────────────────────────────────────┐
│                     PDC Machine                                 │
│  ┌─────────────────┐    ┌────────────────────┐                  │
│  │PdcControlService│    │ Acquisition.Service│                  │
│  │  (WCF Service)  │───→│   (WCF Service)    │                  │
│  └─────────────────┘    └────────┬───────────┘                  │
└──────────────────────────────────┼──────────────────────────────┘
                                   │
                                   ↓ TCP Socket (DACP协议)
┌─────────────────────────────────────────────────────────────────┐
│                     GB Hardware / Simulator                     │
│  ┌─────────────────┐    ┌─────────────────┐                     │
│  │  Real GB Device │    │  GBSimulator    │                     │
│  │  (Production)   │    │  (Development)  │                     │
│  │                 │    │  - Port 12423   │                     │
│  │                 │    │  - ListMode Data│                     │
│  └─────────────────┘    └─────────────────┘                     │
└─────────────────────────────────────────────────────────────────┘
```

- **ViewModel层**: 处理用户交互和状态管理
- **BizLogic层**: 处理扫描业务逻辑和流程控制
- **通信层**: 通过WCF与PDC服务通信，采用双工模式（命令发送+消息回调）

### 1.2 GBSimulator 核心组件

GBSimulator 是一个 **WPF 桌面应用程序**（不是 WCF 服务），用于模拟 GB 硬件设备：

```
GBSimulator (WPF应用程序)
├── SimulatorControlChannel  (控制通道 - TCP Server, 端口12423)
├── SimulatorDataChannel     (数据通道 - TCP Socket发送ListMode数据)
├── SimulatorEventChannel    (事件通道 - 发送扫描事件)
├── SimulatorMonitorChannel  (监控通道 - 系统状态, 端口61024)
├── GBSimulatorViewModel     (UI逻辑和配置)
├── DynamicBedViewModel      (动态床位管理)
├── RealtimeStatsCollector   (实时统计信息收集)
└── HTTP Service (OWIN)      (HTTP API, 端口5000)
```

## 二、StartScan 扫描调用链

### 2.1 入口方法 - StartScan

`ScanProcessConsoleViewModel` 中的 `StartScan` 方法是扫描流程的调度器，根据任务类型（Scout、CT、PET）启动相应流程。

```csharp
public void StartScan()
{
    if (!CanStartScan()) return;
    
    StatusMessageManager.Current.PatientName = ExamPatientViewModel.PatientName;
    var workingScanJob = GetCurrentWorkingScanJob();

    if (workingScanJob != null)
    {
        if (workingScanJob.CurrentState == ProcedureState.NotStarted)
        {
            workingScanJob.UpdateMessageForScanProcess += UpdateMessageForScanProcess;
            PetLogger.PetScanInfo("开始扫描");
            
            if (workingScanJob is PetScanJobViewModel) 
            {
                PetLogger.OperationLog("PET " + ...);
                ECBCTXRAYManager.SendToGB_XRAY_OFF();  // 关闭X射线
            }
            
            workingScanJob.Load();  // 关键调用
        }
        else if (workingScanJob.CurrentState == ProcedureState.ScanDelaying)
        {
            petJob.SkipDelay();
        }
        workingScanJob.StateChanged += workingScanJob_StateChanged;
    }
}
```

## 四、WCF 双工通信详解

### 4.1 核心概念

| 对象 | 作用 | 通信方向 |
|------|------|----------|
| `AcqServiceClient` | 客户端代理，调用服务端方法 | 客户端 → 服务端 |
| `CallbackService` | 回调服务实例，接收服务端主动推送 | 服务端 → 客户端 |

### 4.2 与 HTTP 的对比

| 特性 | HTTP/REST | WCF 双工 |
|------|-----------|----------|
| 通信模式 | 请求-响应（单向） | 双向（客户端可调用服务，服务也可回调客户端） |
| 连接 | 无状态，每次请求新建连接 | 有状态，长连接（Session） |
| 服务端推送 | 需要轮询或 WebSocket | 原生支持回调 |
| 协议 | HTTP | NetTcp（二进制，性能更好）或 HTTP |

### 4.3 建立连接

```csharp
public bool CreateConnection()
{
    AcqCallback = new CallbackService();
    AcqClient = new AcqServiceClient(new InstanceContext(AcqCallback));
    AcqClient.Open();
    AcqClient.Connect();
    AcqClient.InnerChannel.Faulted += InnerChannel_Faulted;
}
```

### 4.4 服务端回调

```csharp
public class CallbackService : IAcqServiceCallback
{
    public event Action<DataSegment> DataReceived;
    
    public void PushData(DataSegment segment)
    {
        if (DataReceived != null) DataReceived(segment);
    }
    
    public void NotifyBedPositionDataCompleted(long seriesID, int bedPosition) { ... }
    public void PushStatistics(StatisticsData statistics) { ... }
}
```

### 4.5 为什么用双工通信

在 PET-CT 采集场景中，客户端需要发送命令（开始/停止采集），服务端需要实时推送数据（原始数据块、统计信息、状态变更）。WCF 双工模式让服务端有数据时立即通过回调推送，实时性好、效率高。

## 五、DACP 协议通信详解

### 5.1 协议定位

DACP（Data Acquisition Control Protocol）是构建在 TCP/UDP 之上的**应用层协议**，不是简单的 TCP 封装。它定义了自己的消息格式（命令头+命令体+应答体）、命令码体系、序列化/反序列化规则以及消息生命周期管理。

### 5.2 通道分工

| 通道 | 角色 | 协议 | 端口 | 说明 |
|------|------|------|------|------|
| **控制通道** | TCP 服务器 | TCP | 12423 | 等待外部客户端连接，接收 DACP 命令 |
| **监控通道** | TCP 服务器 | TCP | 61024 | 等待监控端连接，查询系统状态 |
| **事件通道** | TCP 客户端 | TCP | 动态 | 连接远端，上报状态事件 |
| **数据通道** | TCP/UDP 客户端 | TCP/UDP | 动态 | 连接远端，发送 ListMode 数据 |

**启动顺序**：Simulator 先启动两个 TCP Server（控制通道 12423 和监控通道 61024），等待外部客户端连接。

### 5.3 完整连接与数据流

```
外部程序 (TCP Client)              GB Simulator
      │                                 │
      │    ① 程序启动                    │
      │                                 ├─ 启动控制通道 Listener (端口12423)
      │                                 ├─ 启动监控通道 Listener (端口61024)
      │                                 └─ 启动 HTTP 服务 (端口5000)
      │                                 │
      │    ② TCP 连接                    │
      ├── TCP Connect :12423 ──────────>│
      │                                 │
      │    ③ 发送 DACP 命令              │
      ├── InitEventChannelCmd ─────────>│  初始化事件通道
      ├── InitDataChannelCmd ──────────>│  初始化数据通道
      │                                 │
      │    ④ 启动扫描                    │
      ├── SetListModeOutput = 1 ───────>│  触发 ScanStarted 事件
      │                                 ├── 开始发送模拟数据
      │                                 └── 数据通道持续发送 ListMode 包
      │                                 │
      │    ⑤ 停止扫描                    │
      ├── SetListModeOutput = 0 ───────>│  触发 ScanStopped 事件
```

### 5.4 控制通道命令处理

```csharp
public class SimulatorControlChannel : AsyncServerChannel
{
    public const int LocalPort = 12423;
    
    // 命令处理字典
    private readonly Dictionary<DacpCode, Tuple<Delegate, Type, Type>> handlerDic;
    
    // 示例命令处理
    {
        DacpCode.SetListModeOutputCmd,
        new Tuple<Delegate, Type, Type>(
            new Func<SetListModeOutputCommand, SimpleAcknowledge>(ProcessScanStartStopCommand),
            typeof(SetListModeOutputCommand), typeof(SimpleAcknowledge))
    }
}
```

### 5.5 数据发送模式

| 模式 | 说明 |
|------|------|
| `ContinuouslyReadFileAndSend` | 持续从文件读取 1GB 分块 → 拆分为 64 个 16MB 包发送 |
| `ReadOnceThenSendFromMemory` | 首次读取 16MB 到内存 → 循环发送同一数据 |

### 5.6 三种通信方式对比

| 特性 | HTTP/REST | WCF NetTcp | DACP TCP Socket |
|------|-----------|------------|-----------------|
| 协议层次 | 应用层 | 传输层+ | 传输层 |
| 序列化 | JSON/XML | 二进制 | 自定义二进制 |
| 连接 | 短连接 | 长连接 (Session) | 长连接 |
| 双向通信 | 轮询/WebSocket | 原生 Duplex | 原生双工 |
| 性能 | 一般 | 高 | 最高 |
| 适用场景 | Web API | 内网服务间通信 | 硬件通信 |
