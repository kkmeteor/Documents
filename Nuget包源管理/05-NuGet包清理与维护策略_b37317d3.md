# NuGet 包清理与维护策略

## 一、背景

本地 NuGet 源：

```
http://10.10.11.194:1001/v3/index.json
```

当包已废弃、需要清理时，应根据需求选择**隐藏（Unlist）**或**彻底删除（Delete / 物理清理）**。

## 二、清理方式对比

| 方式 | 效果 | 已安装项目 | 适用场景 |
|------|------|-----------|----------|
| **Unlist（取消列出）** | 不再出现在搜索结果中 | **仍可使用**（不受影响） | **优先推荐**：废弃但不想影响已引用项目 |
| **Delete（删除版本）** | 从源中移除该版本 | 已安装项目更新时自动回退到上一版本 | 彻底移除某版本 |
| **物理删除 .nupkg 文件 / 清库** | 直接从服务器移除包 | 可能导致引用异常 | 仅需彻底清理时，需谨慎 |

> **核心策略**：清理废弃包时**优先使用 Unlist**，使其不再出现在搜索结果，同时已安装的项目仍可正常使用；若需彻底移除再使用 Delete 或直接删除服务器上的 `.nupkg` 文件。

## 三、BaGet 服务器侧的删除方式

BaGet 作为私有服务器，删除包需调用 **REST API**，或直接清理文件系统与 SQLite 数据库中的记录：

- **REST API**：通过 BaGet 提供的删除接口移除包。
- **物理清理**：删除本地文件系统中的 `.nupkg` 文件，并同步清理 SQLite 元数据记录。

> 注意：物理清理涉及服务器存储路径与数据库，操作前应确认服务器结构与元数据一致，避免残留脏数据（详见《01-私有NuGet源环境配置总览》）。

## 四、通过 NuGet CLI 删除特定版本

```powershell
nuget delete <包名> <版本号> `
    -Source http://10.10.11.194:1001/v3/index.json `
    -ApiKey <API Key> `
    -NonInteractive
```

**执行效果示例**：删除 `SV.BL.Serialization` 的 `1.1.3` 版本后，`1.1.2` 自动成为最新版本；已安装 `1.1.3` 的项目在更新时会自动回退到 `1.1.2`。

## 五、⚠️ ApiKey 冲突说明

**原文档对删除/推送使用的 `-ApiKey` 值记录不一致**：

| 操作 | 来源文档记录的 ApiKey |
|------|----------------------|
| 删除包 | `AzureArtifacts`（BaGet私有源地址与认证配置.md） |
| 删除包 | `sinounion`（NuGet打包发布指南.md） |
| 推送包 | `AzureArtifacts` / `sinounion` 均有出现 |

**处理建议**：
- `-ApiKey` 的值取决于本地包源的认证配置。若包源无需认证，可填任意非空字符串或省略。
- 若执行 `nuget push` / `nuget delete` 时认证失败，请向包源管理员确认实际使用的 API Key，而非随意猜测。
